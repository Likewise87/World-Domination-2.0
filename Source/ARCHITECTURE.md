# Sim architecture

How to use this file: open when adding sim, raids, travelers, daily-loop, or strength numbers. Do not use it for keyed copy (`COPY_STYLE.md`), globe icons (`Core/WORLD_MAP_ICONS.md`), tiles (`Core/PLANET_LAYERS.md`), hub windows (`UI_WINDOWS.md`), or Def XML (`Guardrails/DEFS_GUIDE.md`). Index of all guidance: `Guardrails/GUIDANCE.md`. After a code change that moves an owner, flow, or naming alias, edit this file in the same pass.

World-model ownership (one colony, player-only outposts, NPC holdings = Settlements) lives in the always-on rule `Guardrails/.cursor/rules/wd-product-docs.mdc`. Do not rewrite it here. Tick/alloc/save rules: `Guardrails/.cursor/rules/tsa-world-domination.mdc`. **Save compatibility** is a hard priority in those rules — never remove Scribe keys or delete legacy scribed fields.

**Quest offer toggles** live on the **Quests** settings page (`Settings_Window_Quests.cs`, nav icon `UI/Commands/AcademyTeach`), not Experimental.

While settlement intel tracking is on (`WorldComponent_SettlementIntel.IsTracking`), settlement-picking WD quests only offer towns the player has discovered (`WdQuestDiscovery.PlayerSeesSettlement`). Tracking off keeps legacy pick behavior. Victory quest does not pick settlements for issue.

**Common-enemy settlement quest** (`TSA_WD_CommonEnemySettlement`, `WdCommonEnemySettlementQuestHelper`): first offer **day 30**, then reoffers 20–50 days. Success on player-attributed outpost raid / on-map defeat / sabotage wipe / disinformation wipe, and on any `WorldObjectsHolder.Remove` of the tracked town that was not already failed as a non-player wipe (covers third-party artillery `Settlement.Destroy`, buy, player mortar). Non-player WD wipes (NPC/allied simulated raid, incident obliteration, revolt, pollution, NPC mortar) must call `NotifySettlementRemoved` before `Destroy` so the quest fails as taken-by-others. Targets require sane land path from the player home tile.

**Spy-ops intro quest** (`TSA_WD_SpyOpsSettlement`, `WdSpyOpsSettlementQuestHelper`, `GameComponent_WdSpyOpsSettlementQuest`): one offer after days 10–16. Success = successful sabotage or disinformation on the tracked shared-hostile town (strength damage enough; hooks in `Gizmo_Sabotage` / `Gizmo_Disinformation`). Any end → permanently done. Def under `1.7/Defs/QuestScriptDefs/`.

**Fortify intro quest** (`TSA_WD_FortifySettlement`, `WdFortifySettlementQuestHelper`, `GameComponent_WdFortifySettlementQuest`): one offer **6–12 days after SpyOps ends** (or days 16–24 if SpyOps setting off). Success = successful Fortify on the asker's town (`Gizmo_Fortify`). Any end → permanently done. Def under `1.7/Defs/QuestScriptDefs/`.

**Colony road-link quest** (`TSA_WD_ColonyRoadLink`, `WdColonyRoadLinkQuestHelper`): first offer **day 14**.

**Scout the world map quest** (`TSA_WD_ScoutWorldMap`, `WdScoutWorldMapQuestHelper`, `GameComponent_WdScoutWorldMapQuest`): one offer 1–5 days after intel tracking turns on (skipped if a player scout already launched). Asker = closest ally/neutral WD settlement (Ally wins distance ties); on issue Discover + 6-tile FoW reveal. Success = live player scout traveler (`WorldActions_PlayerScout` notify + GC poll). Reward = ThoughtDef `TSA_WD_StartedScouting` (+5 mood, 5 days). Def under `1.7/Defs/QuestScriptDefs/`; thought in `Common/Defs/ThoughtDefs/`.

## Outpost power

SSoT: `OutpostPowerGrid` / `WorldComponent_OutpostPowerGrid` / `OutpostPowerReach` (`Outposts/OutpostPowerGrid.cs`). Economic Difficulty `enableOutpostPowerRequirement` (default on; Easy difficulty preset off); Medieval forces off via `OutpostPowerGrid.Enabled`. Player-facing electricity UI/strings (Overview Power column, upgrade power demand / remote-power benefit rows, power-plant product lines, DesirePower radius gizmo) also key off `Enabled` — no watt copy when the feature is off. Medieval toggle dirties the grid; Economic power checkbox is greyed while Medieval is on. XML `powerDemandWatts` + `unpoweredOutputFactor` on `OutpostDefExtension` and upgrade `powerDemandWatts` via **1.7/Patches only** (`WD_OutpostPower_Tags.xml`, `WD_OutpostPower_UpgradeDemand.xml`).

**Allocation (food-parity):** Plants use `PowerLogisticsMode` Smart/Manual. Persisted `powerManualLinks` (tile→tile→watts). Smart deficit-fills reachable outposts to 100% demand before the next; **Keep** = budget − Σ(out) → colony Harmony inject (`Outpost_PowerPlant` / `WorldComponent_OutpostPowerPlant`). Colony split: if any eligible `TSA_WD_RemotePowerSpot` (1.7; wired `CompPowerTrader` 0 W + relative `sharePercent`) exists on the player-home map, Keep goes only to those spots' nets (weights normalize to 100%; same-net spots sum); otherwise equal share across every colony net. Manual edits outpost links via Logistics Electricity tab (`WITab_Outpost_Logistics`). Load: `ExposeData` LoadingVars dirties Smart + resets soft fingerprint (same contract as food logistics). Heal: `TryReconcileSmartFromFingerprint` on power tick + logistics tab `OnOpen`; `EnsureAllocationFresh` / Smart complete defer while `ProgramState != Playing` so early PowerNet callers cannot clear dirty after an empty pass. No colony destination row. No XOR colony/outposts gizmo.

**Production factor:** `GetProductionPowerFactor` lerps `unpoweredOutputFactor`→1 by supplied/demand. **Range nerf:** `ApplyUnpoweredRange` / `ApplyUnpoweredRadius` multiply trade, recruit, embassy, mortar, AA, Rapid Response intercept, and warehouse aura radius by Economic Difficulty `unpoweredRangeFactor` (default 0.70) while demand is unmet. Auto-turret spawn and similar combat gates stay binary via `IsPowered`.

Yield hooks (must stay in sync): `GetEffectiveProductionOutputMultiplier`, `ApplyExpertAndWarehouseYieldMultipliers` (recruit/trade/embassy/scavenge), `ComputeDailyProductionUncached` (food), `GetPointsPerTick` (research). **Do not** put power into `GetSoftProductionBonusMultiplier` (Academy XP). Dirty hub: `OutpostPowerGrid.NotifyOutpostPowerDirty`. Reach reuses `maxLogisticsRange`.

Player pawn drop-pod AA: `WorldActions_Traveler_MortarAa.ResolveRapidResponseDropPodAaHit` (per-pawn hit/kill/crash) + `WdDropPodCrashUtility` / `WorldObject_WD_DropPodCrashSite`. Crash maps reuse `MapComponent_ReinforcementTimer` with a hostile Settlement proxy for ally timing.

## Outpost Ideology slave removal (SELECT vs COMMIT)

SSoT: `OutpostPawnIdeologyUtil` (`Outposts/OutpostPawnIdeologyUtil.cs`).

| Layer | API | Rule |
|-------|-----|------|
| **SELECT** (checkboxes / select-all) | `CanToggleOutpostRemovalSelection` | Free non-slave humanlikes always selectable; slaves (and escort dependents) only when a free occupant is already selected. Leave-behind is **not** checked here. |
| **Prune** | `PruneDependentRemovalSelection` | After selection mutations: drop slaves if no free occupant remains selected. |
| **COMMIT** (transfer / remove / drop-pods enable) | `BulkRemovalSelectionIsAllowed` | Full evacuate OK; else keep ≥1 free on outpost; slaves leaving need a free leaver. Tips via `TryGetBulkRemovalRejectReason`. |

### Unescorted drop-pod cargo (player holdings only)

SSoT: `PlayerPawnTransferUtility` (`Outposts/PlayerPawnTransferUtility.cs`) + `WdRrInterceptDropUtility.DisposeUnescortedDropPodCargo` (`Travelers/WdRrInterceptDropUtility.cs`).

| Rule | Detail |
|------|--------|
| **When** | `viaDropPod` **and** destination is a live **player** outpost or colony (`AllowsUnescortedDropPodCargo`). Land caravans still need a free escort. |
| **Cargo** | Prisoners, Ideology slaves, and mechanoids only. Animals / vehicles / shuttles stay blocked without an escort. |
| **SELECT / COMMIT** | Pod→player dest waives free-escort / slave-accompaniment gates in validate + ideology prune (`GroupIsUnescortedDropPodEligible`, `waiveSlaveAccompaniment`). WITab / All Player Pawns may select slave/mech-only groups in drop-pod mode. |
| **Launch** | Rapid Response drop-pod spawn sets `WorldObject_Traveler.unescortedFireAndForget` when the pawn list has no free escort (`PawnListHasFreeEscort`). Scribed. |
| **Abort / dead dest / AA** | Never `ReturnHome` / player caravan. Call `DisposeUnescortedDropPodCargo`: free captives to world (non-player), destroy mechs, letter `TSA_WD_PawnDropPod_Unescorted*`. Escorted pods keep the existing return/intercept paths. |
| **Arrival at player outpost** | `ExecuteRapidResponseDropPodArrival` / `ReturnPawnsToOrigin` re-capture `IsPrisonerOfColony` via `TryHandleArrivingPrisoner` (same as land / vanilla transporters). Never `AddPawn` prisoners into Occupants. |

**Player Ideo assign (Ideology DLC active only):** `ApplyPlayerPrimaryIdeoIfActive` sets the pawn to `Faction.OfPlayer.ideos.PrimaryIdeo` via `SetIdeo`. Call sites: `RecruitPrisonersBatch` (after `SetFaction`) and `Outpost_Recruiting.GenerateRecruitPawn` (Recruiting outpost production and conquest founding pawns). No-op when Ideology is inactive or there is no primary Ideo.

**Cheap Combat kind band:** `Outpost_Recruiting.BuildPawnKindPoolFromFaction` keeps only humanlike Combat options with `Cost <= cheapestCost * CheapKindCostBandFactor` (1.20). Shared by recruiting, conquest founding workers, and virtual captives (`OutpostPrisonerUtility.GenerateVirtualCaptivesFromEnemyLosses` rolls that pool via `GenerateHostilePawn`; no full-strength raid group). Manual defense map harvest is unchanged.

## Outpost Armory (loose gear)

SSoT: `CompOutpostArmory` + `OutpostArmoryUtility` (`Outposts/Armory/`). Opt-out experimental setting `experimentalOutpostArmory`. The Type filter shared by the Armory dialog and All Player Gear (`ArmoryTypeFilter`: Guns / Bows / Melee / Grenades / Ammo / Armor / Headgear / Torso / Legs / Medicine / Drugs / Food / Other) is owned by `OutpostArmoryUtility.TypeFilterFor` (single display kind), `MatchesTypeFilter` (Headgear / Torso / Legs match by apparel coverage and overlap) and `BuildTypeFilterChoices`. Armor is the vanilla `ApparelArmor` category tree (helmets plus body armor). UI must not re-classify.

Two stores side by side, because one model cannot hold both:

| Store | Type | Holds | Scribe key |
|-------|------|-------|------------|
| `Stock` | `List<ThingDefCountClass>` | Everything ordinary, grouped by `def + stuff + quality` | `armoryStock` (non-warehouse) |
| `uniques` | `ThingOwner<Thing>` (`ParentHolder` null, `dontTickContents`) | Items passing `IsIrreplaceable`: bladelink, art, quest tags, generated names, tainted apparel (taint is never cleared) | `armoryUniques` |

**One item store per outpost.** On a warehouse, `CompOutpostArmory.Stock` *is* `CompOutpostWarehouse.storedItems` (`UsesWarehouseStock`), so the Armory dialog and the Warehouse Storage tab read and write the same rows. A warehouse's own `armoryStock` stays scribed for save compatibility but is not the live store. Consequences: armory rows on a warehouse count toward warehouse capacity and auto-ship; `ArmoryRows()` is the filtered view (`IsArmoryItem`) for gear UIs; `GetTotalItemCount` counts gear only; `ClearAndDestroyAll` never clears warehouse stock. Store rows are always plain (`CompOutpostWarehouse.PlainStockRow`): runtime `WdStockExtras` are stripped on deposit so `SameStockIdentity` merges cleanly.

Intake SSoT: `OutpostStorageUtility` (`TryStoreThing`, `DepositRows`, `DepositUniques`). Caravan dissolve, pod arrival, delivery arrival, traveler refunds, and **manual outpost defense / trench victory salvage** (`OutpostDefenseLootUtility.SalvageMapIntoOutpostArmory`: loose map armory items + corpse gear into the defending outpost; not building inventories) all go through it: armory first, then warehouse stock; anything neither accepts is refunded to the colony, never destroyed.

Destination SSoT: `Outpost_Warehouse_Delivery.IsValidShipmentDestination(target, sender, rows, uniqueCount, virtualFood, out rejectKey)`. Armory items (gear, food, drugs, medicine, ammo) and uniques may go to any player outpost, colony or warehouse; other goods only to a colony or warehouse; virtual food only to another player outpost. No caller re-implements this.

Food is always stored as items. Nothing auto-converts on arrival or intake. `OutpostFoodConversion.ConvertRows` is the only path to virtual food: the Warehouse tab converts checked food rows at their send amounts, the Armory dialog converts all stored food. Both clamp to `PoolHeadroom` and leave the remainder as items.

Grouping only works because `OutpostArmoryUtility.Normalize` heals to max hit points on deposit, which collapses `CompOutpostWarehouse.StockKey` down to `def + stuff + quality`. Taint and biocoding are never cleared anywhere: tainted or biocoded gear is irreplaceable and kept as a real Thing in `uniques` (repaired, otherwise unchanged). Biocoded items get a "biocoded" tag via `StoredThingTag`; tainted apparel has no label tag but is drawn in `TaintedColor` (yellow) with `TaintedTip` in the Armory and All Player Gear. Under CE, deposit also unloads the magazine (rounds credited as ammo stock) so guns stay stackable.

Occupant moves are map-free: never `TryDropEquipment` (routes through `MapHeld`) and never `Wear(ap, dropReplacedApparel: true)` (silently destroys the replaced apparel when `pawn.Map == null`). Conflicting apparel goes to the store first.

**Equipment** (toolbar float menu on `Dialog_OutpostArmory`, cyan Transfer icon): checkboxes on occupant and store rows; all strip/equip actions use the selection only. Menu order: Auto Assign Gear, Auto Assign Drugs, Strip weapons / armor / apparel / other inventory / drugs. `TryQuickEquip` fills empty primaries and free apparel layers from checked store weapons/apparel including clothing and armor (better of Melee vs Shooting sets priority and weapon type; within that type highest silver MarketValue; fall back to the other type only if none remain; never strips). `TryAutoAssignDrugsFromStore` shares armory drugs (up to 5 each) and skips teetotalers (`DrugDesire` degree -1). Other-inventory strip matches the Other Inventory column (not food/drugs/ammo/medicine). Food/Ammo remove and assign also use checked occupants only (`StripInventoryMatching` / `TryAutoAssignFoodFromStore` / `TryAutoAssignAmmoFromStore` with `onlyPawns`). Convert food remains whole-store.

Teardown: `WorldObject_WD_Outpost.Destroy` / `PostRemove` call `ClearAndDestroyAll`; loose stock dies with the outpost and retreat caravans do not evacuate it.

Shipping reuses the goods traveler. `OutpostStorageShipping.TryLaunch` is the one outpost send path (Armory dialog, Warehouse tab, All Player Gear, warehouse auto-ship): it checks the destination rule, then `CanLaunchFrom` (manual defense, pod research, strength), withdraws rows, uniques and virtual food, and rolls all three back if `SpawnDeliveryTravelerFrom` returns false. All Player Gear land/drop mode honors `OutpostDispatchMode` per origin (same SSoT as warehouse Ship Now / upgrade dispatch), plus a window toolbar override for origins without a dispatch comp. `ColonyArmoryLaunchUtility.TryLaunch` does the pawn-free colony launch (free, since a colony has no `CompViralSpread` pool); it re-checks map stacks at launch and puts everything back on the map if the spawn fails. All Player Gear strips outpost pawn gear into the store via `TryStoreFromPawn` only after `CanLaunchFrom` passes, so a reject leaves it stored, not lost. Rows at an outpost under manual defense, gear in world caravans, and worn/carried gear on a map under an active hostile assault/siege lord (or an active WD outpost-defense / caravan-clash encounter) are not selectable. Ordinary rows ride `deliveryItems`; uniques ride `cargoUniques` on the traveler. Cargo destroyed in transit is gone, including strength-depletion attrition; only a genuine `AbortTraveler` cancellation refunds (`RefundCargoToOrigin`: outpost origin re-stores via `OutpostStorageUtility`, colony origin drops on the map).

## Outpost occupant skill XP

## Daily loop

`WorldComponent_SpreadManager.WorldComponentTick` (`WorldActions_Orchestrator.cs`):

1. Once per day (`60000` ticks): `CalculateDailyBudget` → `DailyWorldSnapshot.Build` (`Core/DailyWorldSnapshot.cs`; enumerates **WD participants** only via `IsWdParticipant`) → revolt (top-empire victims; prefer up to two Turtle-edge-20 clusters, else legacy scatter fill) / forward assault (Vanguard|Invasion) / **Isolation Pressure** (`WorldActions_IsolationPressure`: when fewer than 3 hostile factions threaten the player, one faction not on per-faction CD may be forced to found 1–2 settlements 10–15 tiles from the player; chance Def 40%; stage gate Def Always; founding raid+defense shields) / diplomacy / threat → enqueue faction action slots. Special-event cooldowns: `WorldActions_SpecialEventCooldown` (war / revolt / forward assault; optional shared). **Strategy on Settlement Loss** is reactive (`WorldActions_DesperationRaid.NotifyNpcSettlementLost`): cluster pressure (hostile offense within 15 tiles of any cluster site (membership edge 20) ÷ cluster offense) + min size + `gateThreatDesperation` (Def Always; **not** set by Easy/Medium/Hard presets) → `settlementLossStrategyFireChance` (Def 40%; fail does not stamp CD) → fork Turtle vs desperation by equal-share relative strength × likelihood slider (`desperationChanceOnLoss` Def 0.30). Desperation stamps global `desperationRaidCooldownUntil` (Def 30 days; legacy `desperationRaidCooldownByFaction` still Looked). Reactive Turtle stamps faction `turtleCooldownByFaction` only. **After Strategy**, `WorldActions_Utils.TryMarkDefeatedIfNoSettlementsLeft` sets vanilla `faction.defeated` when that loss emptied the faction (skips mid-refound PackUp/Turtle/AssaultRally travelers); `WorldStatsUtils` keeps defeated zero-rows on World Stats / dashboard rank (`GetLivingNpcStrengthTotals` still skips them for sim N). Load: `ClearFalseDefeatedFlags` on `FinalizeInit(fromLoad)` (heal stuck defeated while surface settlements remain); true-wipe mark only on settled `ExecuteWhenFinished` bootstrap (`MarkTrueWipeDefeatedFlagsIfSettled`) - never mass-mark in early FinalizeInit. Reactive Turtle uses ally radius (migrate outside / fortify-in-place if zero migrants). Daily Turtle stays separate (`WorldActions_Turtle.TryTrigger`: Def chance 0.25; faction CD Def 10 days; global daily CD Def 5 days on `dailyTurtleCooldownUntil`; leaves need offense ≥400; pack into existing dig-ins — primary, T3/T4, up to 2 reserved strong T2 vessels — preferring T3-cap room for multi-T3 consolidate / ally reinforcements; rare last-resort T4-cap overflow on existing hubs; no turtle founding). Incident obliteration does not start Strategy (but still marks defeated if last site). **NPC Fortify** (`WorldActions_NpcFortify`): threatened settlements build the shared turtle kit (`WorldActions_FortifyKit`) locally in phases (road traps + ensure road exit → road blocks → AT turrets); Turtle / desperation place the full kit instantly via `TryPlaceFortifyKit` (T1: Spike + Light block + 1 Light AT). If Fortify is picked but cannot launch, orchestrator re-rolls once among other eligible weights. **Reactive loss bus and daily threats require `ProgramState.Playing`** (no Strategy / FA / Turtle / action queue during world gen or Select Starting Site). Vanguard packs 5–7 far sites and mass-relocates; Invasion reuses the same pick gates but launches 5–7 coordinated raids with homes staying (`WorldActions_Raid.TryLaunchCoordinatedInvasionRaid`). Pack→rally→absorb→Raid for Desperation: `WorldActions_AssaultRally` (`TravelerMission.DesperationRally`; `isDesperationRaid`). ### Mid/Late attrition rest

When `gateThreatAttritionRest` passes (`WdEscalation.PassesGate`, Def FromMid), walking travelers that hit `attritionRestMinRatio` of `initialStrength` from **attrition only** stop (`StopDead`), regenerate toward 100% of initial (`TravelerAttritionRest`), then `StartPath` again. Suppress begin-rest if recently hit by mortar/AT/AA (`lastHostileFireTick` + fire-grace days), a hostile AT can engage them, or remaining path ETA ≤ near-dest buffer (Def 0.1 days). Hostile strength damage while resting (`TravelerAttritionRest.NotifyHostileFire`: mortar/AT/AA shells, open-field traveler/caravan/AT clashes, spike traps) cancels rest and resumes the journey immediately; resting travelers also leave if a hostile AT becomes able to engage. Attrition still clamps at the rest floor when rest is suppressed; combat/traps/pollution can push live strength below without snapping up. Forecast helpers in `TravelUtils` (`GetMinTravelEfficiency` via `TravelerAttritionRest`) floor predicted efficiency at the rest ratio so raid gates / projected arrival assume ≥80% when the feature is active. Regen Def is 2%/hour (~10h from 80% to 100%). V1 has no special rest-camp clash map.

**FoW perf (best practice):** Sight gizmo rings are unrelated to FoW. Tracking does Discover/LOS; FoW draw does tile disks. The Sight hex fill (`WD_WorldLayer_OutpostCoverageFill`, translucent gold LOS/Awareness) is a pure radius overlay like the food/warehouse discs — it is never coupled to FoW mesh regen. It stays flicker-free because the Awareness radius only changes at day boundaries: `GetLosGrowthFactor` derives whole days from ticks (60000/day), so `GetMaxLos` is constant within a day and `TrySetTarget` rebuilds the disc mesh at most once per day instead of every tick.

- **Known-first.** Knowledge is permanent (`knownSites` / `knownTravelers`), so every spotting loop tests the known set before any `GetComponent`, radius or distance. The hop pass (`SpotTravelerOnHop`) tests both directions per pair (does the site's faction still need the traveler, does the traveler's faction still need the site) and skips the pair when neither does.
- **One distance per pair.** `WorldComponent_SettlementIntel.TileDistance` = rounded `ApproxDistanceInTiles`, the same value `GetDistance` returns. Intel / FoW paths never call `WorldActions_Utils.GetDistance`: it writes the saved 65k `distanceCache`, and mobile tiles would evict the stable settlement pairs. Outside intel the same rule holds: any pair with a mobile tile (traveler, caravan, pod) uses `WorldActions_Utils.GetDistanceUncached` (mortar, AA, AT interception, attrition, proximity letters); `GetDistance` is for stationary pairs only.
- **Hop pass angular cull.** A traveler is unknown to most distant factions, so known-first alone would still pay a comp lookup and a distance for nearly every settlement. `EnsureHopCullCache` keeps a unit direction and `cos(sight angle)` per settlement; one dot product rejects a settlement outside `max(site Awareness, traveler Awareness)` (+1 tile, +5%) before any lookup. Arc per tile is measured from sample tile pairs (`CalibrateRadiansPerTile`); if the samples disagree the cull switches itself off. Rebuilt on settlement spawn, count change, day rollover and stationary LOS change. The player colony is never culled (live radius).
- **Daily pass is sliced.** `DailyLosPass` only queues the stationary observers; `ProcessDailyLosQueue` runs `DailyLosObserversPerTick` (16) per world tick. Runs in one go outside `ProgramState.Playing` (world-gen). The queue is runtime-only; after a load the session bootstrap covers settlements and outposts.
- **Icon version.** The icon hide/dim cache keys on `iconVersion`, bumped only when the FoW view faction's knowledge changes (plus load / bootstrap / site clear). `Version` still bumps on every faction's discovery for the Stats tab.
- **Range before sight** for weapons: mortar pick checks range first, then `IsCurrentlyVisibleToFaction`. AT / AA stay range-only (no sight test).
- **Sight disks are per observer and incremental.** `WdFowTileMemory` keeps one tile list per view-faction observer and per-tile counts. `MarkVisibleStructureDirty` (own mover hop, stationary LOS change, daily pass, 90t observer diff) makes `EnsureVisibleCacheFresh` re-flood only observers whose tile or radius changed and release vanished ones; no whole-planet loop. Full rebuild only on view switch / tile-count change. Never on Discover `Version`, never via `InvalidateFowDrawCache`, never from a draw layer (layers read bits and dirty queues only).
- **Sight queries read tile counts.** Icon bright / dim (`ClassifyFowTarget`) and `IsInCurrentSightOfFaction` for the view faction are O(1) reads (`IsTileVisibleBit` / `IsTileInAwareness` / `TryGetViewAwareness`). Other factions use an observer loop with the same `ApproxDistance ≤ Awareness` test, observers collected once per (faction, tick).
- **Explored tiles: player only.** `RevealTilesInRadius` returns for NPC factions (unless it is the active debug view) and skips a (centre, radius) already flooded this session (`revealMemo`). Debug "View World as" an NPC starts from that faction's current sight and accumulates only while viewed. Saves write the player's explored blob only (same keys; NPC blobs in older saves are dropped at the first tracking tick).
- **Radius caches.** NPC settlement Awareness is day-cached; player colony / outpost Awareness (pawn count) is cached 250 ticks and dropped by `NotifyStationaryObserverLosChanged`.
- **Timing.** With verbose logging on, one `[WD Perf] FoW/LOS day:` line is logged when the daily queue drains (daily pass ms and ticks, hop count + ms + settlements culled, icon rebuilds + ms, disk refreshes + ms), plus one `FoW hop cull on/off` line at calibration.

## GUI perf: never scan AllWorldObjects or DefDatabase per frame

Right-side `Alert`s and world-map `WorldComponentOnGUI` run every frame; `AlertsReadout` re-checks active alerts continuously. Map float buttons and open dialogs are the same class of hot path. Do not walk `Find.WorldObjects.AllWorldObjects` or rediscover defs (`DefDatabase<T>.AllDefsListForReading`, category `DescendantThingDefs`, ammo-set walks) in these paths.

Read maintained/throttled registries instead:

- **Player outposts:** `WdPlayerOutpostCache.PlayerOutposts` (`Core/WdPlayerOutpostCache.cs`) — throttled snapshot (one scan per ~1800 ticks), self-healing (backwards-clock guard). Used by `Alert_WDOutpostUnusedExperts`, `Alert_WDOutpostNoProduction`, `Alert_WDConstructionInsufficientStrength`, `Alert_WDConstructionInsufficientMaterials`, `Alert_WDDropPodDeliveryInAaRange`, and the underlays' player-outpost draw. Consumers still null/`Destroyed`-check each element (a since-destroyed outpost can linger up to one interval; guard `AlertReport.CulpritIs`).
- **Travelers:** `WorldObject_Traveler.LiveTravelers` (SpawnSetup registration is idempotent; Destroy removes all registrations). `WorldActions_Orchestrator.FinalizeInit` calls `RebuildLiveRegistry()` (and again after remnant cleanup on load) + `WdPlayerOutpostCache.Invalidate()` so stale static state cannot carry across save loads in one session.
- **AT turrets:** `WorldObject_AT_Turret.LiveTurrets` (same SpawnSetup / Destroy / FinalizeInit rebuild). Caps, `HostileAtCanEngage`, and NPC nearest-AT pick this list — not `AllWorldObjects`. Raid/Turtle assess credit: `AtTurretUtility.SumOwnedDamageCredit` (`damage/2` per live owned AT) is folded into `CompViralSpread.GetTotalLocalDefensePower` and also added in Turtle `SumClusterOffense` (pressure). Feature B maraud continue applies Def 15% traveler strength tax and decides on post-tax power (`TargetOfOpportunityUtility.TryContinueMarauding`).
- **Advanced buildings / NPC artillery turrets:** `WorldComponent_AdvancedBuildings` (`All`, `At(tile)`, live `OwnedBy` via `builtBySettlement`, `Version`). Alerts, overlays, and inspect read this registry — not `AllWorldObjects`.
- **Bridge / AT construction queues:** `WorldConstructionProjectRegistry` (comps with `bridgeSpanTiles` length >= 2 or `atTurretPlannedTiles`). Lock/reserve walks it; invalidate on commit/clear, rebuild on FinalizeInit. Do not use the 30s `WdPlayerOutpostCache` for these locks. Crew abort scans `LiveTravelers` by origin + mission.
- **Def catalogs (shells, ammo, etc.):** discover once after defs are loaded (lazy first use is fine). Hot paths only read the cached lists and cheap runtime flags (e.g. outpost upgrade tier). Example: assault artillery mortar shells in `RaidLogic/WD_AssaultArtillerySupport.cs` (`EnsureShellCatalog`) — never re-scan shells when building tooltips or dialog rows.
- Underlay raid-target caches are tick-gated (30t), not per-frame. Alert `GetLabel()` strings are cached (no per-frame `Translate`).
- **Pawn roster tables:** columns come from `PawnRosterColumnRegistry` and rows are rebuilt on a dirty flag (`PawnRosterViewState.Revision`, `PawnRosterTraitFilter.Revision`, `PawnRosterHediffFilter.Revision`, row count) or a short frame interval, never every frame. Extras read cached `PawnRosterRowData`. Owners and rules: `UI_WINDOWS.md` § Roster family.
- **Hub list tables (many rows):** record the scroll outer height (`lastScrollViewportHeight`); in `DrawRow`, early-return when the row Y is outside `[scrollPos.y - rowH, scrollPos.y + viewportH)`. Keep full `viewRect` height so the scrollbar still matches the list. Never call `Translate(args)` inside `DrawRow` — cache those strings on the row at rebuild (or on the window when the filter/destination changes). Pattern: `Window_AllPlayerPawns`, `Window_AllPlayerGear`. A `MaxRows` collect/sort cap is separate from draw cost.

## Settings defaults

`Def*` constants on settings are the defaults. Tooltips never hardcode them (`COPY_STYLE.md`).

## Settlement tier promotion

SSoT for **promotion** (NPC settlements):
- **Soft promotes** (Develop `TryUpgrade`, trader arrival, Gift/Buy/Bribe `TryPromoteTierFromInvestment`): `CanUpgradeTierFully` = pyramid support (`MeetsPyramidSupportForUpgrade`, `sameTierNeighborsToUpgrade*` as one count for peers + each lower tier) **and** `CanPromoteNextTierRegionally` (`localMaxT*` room). Densification measuring stick is `localTierClusterRadius` (Cluster radius), not `expandMaxRadius`. Founding ring stays `expandMinRadius` / `expandMaxRadius`; T1 saturation (`IsTargetSaturated`) uses Cluster radius.
- **Turtle** strength-deposit promotes (`DepositStrengthWithRegionalPromotes` / `TryPromoteOneTierFromStrengthDeposit`): regional `CanPromoteNextTierRegionally` only (crisis bypass; no pyramid).
- Strength refunds and `AddStrength` never promote (clamp to current tier max). `CheckTierUpdate` demotes only when asked. Pack-up founding via `SetState(massRelocationTier)` and worldgen are separate and can still place T4s without that regional gate.

## Trader arrival rewards

SSoT: `CompViralSpread.ApplyTraderArrivalReward` (sender + receiver on `ExecuteTraderArrival`; intercept loot uses receiver strength). Always applies flat strength. At/near offensive cap (T1–T3 only): independent rolls for **tier-up** (`traderTierUpgradeChance*`, defaults 20/15/5) and **infra** (`traderInfraChance*`, defaults 20/15/10). Tier-up uses `CanUpgradeTierFully` (same pyramid + regional gates as Develop). Infra chances use pre-promote tier; placement uses final tier: prefer instant advanced building via `WorldActions_AdvancedBuildings.TryInstantPlaceFromPool` (`BuildPool` + `Place`, no builder/cooldown), else one kit-tier AT via `WorldActions_FortifyKit.TryPlaceOneAtTurretForSettlement` (T1/T2 Light, T3 Medium). Outposts / player map / T4 / below-cap: strength only. Action Log via `LogTraderTradeParty` (`TraderArrivalRewardResult.InfraLabel`).

**Colony map spawn:** `Trader_OnPlayerColony.TrySpawnTraderOnPlayerColony`. For AI/story arrivals (`traderKind == null`) from the Empire with Royalty active, `traderEmpireTributeCollectorChance` (Def 20%) may fire soft-resolved `CaravanArrivalTributeCollector` (`forced`) instead of `TraderCaravanArrival`; ordered traders and failed/unavailable tribute fall back to a normal trader. World rewards/goodwill above still apply either way.

## Do not copy (sim)

- NPC settlement attack range: call `SettlementAttackRangeUtil.GetNpcSettlementAttackRangeWithZeal`. Player outpost range is a different knob (`raidTargetRadius` + strategist in `Action_Outpost_LaunchAttack`); do not fold it into the NPC util.
- Raid outcome interpolation (siege / settlement / outpost): `RaidCasualtyModel.GetForecast` / `Resolve`. Do not add a second siege interpolator.
- Open-field traveler/caravan/AT melee: win% + winner-loss tiers owned by `OpenFieldClashUtility` (`GetOpenFieldAttackerWinChance`, settings `openFieldWinPower` / `openFieldWinnerLoss*`). Soft clamp 2–98%; at **10×** (Def `DefOpenFieldCertainWinRatio`) win chance is certain 100%/0% (skips diplomacy upset). Loser wiped. Reuses `RaidSeverityDefaults.AttSeverityOnAttWinAt` for margin shares only; do not route open field through full `RaidCasualtyModel.Resolve`. Action Log / details: `Window_CaravanClashDetails` + `RaidUIUtils.FormatOpenFieldLogSuffix` (role-neutral win type + winner loss %; no attacker/defender siege labels).
- Fortify kit layout (r=1 AT, r=2 traps/blocks, ensure road exit, tier `GetKit`): `WorldActions_FortifyKit`. Daily NPC Fortify and Turtle / desperation instant kit share it (T1 included); do not add a second kit interpolator.
- Timed buffs on SpreadManager: Leader, Nimble (multi-faction set + per-faction CDs), Expansionist, and coalition use separate fields (`currentWorldLeader`, `activeUnderdogs`, `expansionistZealFaction`, `antiLeaderCoalition*`). Leader and Nimble are mutually exclusive for one faction (nimble clears leader; leader will not apply onto an active underdog). Coalition/zeal stay independent; if the coalition target becomes nimble, remaining coalition duration clamps to 3 days. Do not add a fifth loose expiry field.
